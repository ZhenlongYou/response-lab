## 本轮修复

审查中确认并修复了两个会影响分发的问题：

1. 旧 Windows 构建只检查 `ResponseLab.exe` 是否存在。现在构建完成后会实际运行 `ResponseLab.exe --self-test` 和 `ResponseLab.exe --gui-smoke-test`，任一失败都会阻断 artifact 上传。
2. 大时间原点与皮秒级采样间隔组合时，首对 float64 时间戳的舍入误差会导致错误采样率或误报“BIN 导出时间必须等间隔”。现在由完整记录跨度恢复标称间隔，同时继续逐块拒绝超过加载合同的局部时间抖动。

## 发放前人工检查

在干净 Windows 10/11 x64 办公电脑上执行以下检查：

1. 解压完整 artifact，双击 `ResponseLab.exe`，确认六个页签、字体、图标和绘图组件可见。
2. 导入两份拟合脉冲和一份已知 AG10 BIN，完成比较、补偿、输出预览和 BIN 导出。
3. 用 EXE 重新导入导出的 BIN，核对点数、采样率、时间原点和代表性波形。
4. 用同一波形的 CSV 做一次对照；随机裸 BIN、未知版本和截断文件应给出明确错误。
5. 运行影响频段的 LFP、频域 RMS、眼高和眼宽代表性流程。
6. 断网后重新启动，确认程序不依赖 GitHub、构建路径或开发环境。
7. 记录 Windows 版本、电脑型号、artifact 名称、EXE SHA-256、测试文件哈希和结论。
8. 若 SmartScreen、杀毒软件或公司应用白名单阻止运行，应由 IT 完成代码签名或白名单流程，不能通过关闭终端安全策略绕过。
